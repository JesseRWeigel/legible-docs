legible-docs, measured

A command line tool and a browser extension that reflow public notices, school letters, and benefit forms for dyslexic and low vision readers, and report in numbers what they changed and what they could not.

Every figure on this page was produced by running the tool over the corpus in the repository. The page is generated from that run by scripts/build-docs.js, and scripts/verify.sh rebuilds it and fails if it differs from the committed copy, so it cannot quietly go stale.

Recheck: this page recomputes its own contrast figures in your browser. If scripting is off, the numbers below are the ones published and nothing has rechecked them.

What it does to a document

The tool never removes or rewords the document's text. A benefit notice is a legal document and the wording is the thing being delivered. What changes is presentation: the typeface, the tracking, the line height, ragged right instead of justified, alternating paragraph shading, real headings instead of bold paragraphs, and colours moved until they meet contrast. An optional plain language summary from a local model is placed alongside the original, never over it, with a visible note saying a machine wrote it.

Reading order

The defect that looks fine on screen: two stories side by side in a layout table read, to a screen reader, as row one of the left story, row one of the right, row two of the left, and so on. The page looks right and linearises wrong. Each corpus document ships a hand written .order.txt listing its blocks in the order a person reads them aloud, and the measurement is the Kendall tau distance between that and the order the markup produces.

Contrast

The ratio is WCAG 2.1's: linearise each sRGB channel, weight them 0.2126, 0.7152 and 0.0722, then take (lighter + 0.05) / (darker + 0.05). The linearisation matters. Drop it and #767676 on white reads 2.05:1 instead of 4.54:1, which is the difference between failing a colour that passes and passing one that fails.

The large text exception

WCAG asks for 4.5:1 normally and 3:1 for large text, where large means 18pt, or 14pt when bold. One threshold for everything is wrong in both directions. The thresholds are converted from points exactly, so 18pt is 24px and 14pt is 18.667px. Rounding the bold threshold down to 18.66px, which several checkers do, lets bold text at 13.995pt claim an allowance it has not earned.

Alt text

An empty alt is the correct markup for a decorative image and a silent information loss on an informative one. A checker that flags every empty alt buries its real findings under one false positive per divider rule on the page, and a checker that accepts any alt at all passes alt="image". So the tool sorts images into four outcomes, and it never writes a description for an image it cannot see.

What this tool cannot check

  • It cannot see an image. No alt text is ever generated. An image with no usable description is flagged in the output for a person to write, and the missing alt is left missing so every other checker still reports it.
  • It cannot read a scanned PDF. A page with no text layer is reported as needing optical character recognition. No text is invented for it.
  • It does not fetch external stylesheets. A colour that lives in a linked CSS file is reported as unmeasured, with a warning naming the file.
  • It does not evaluate at-rules. Colours inside @media or @supports are skipped and warned about rather than guessed at.
  • The command line tool has no browser. It implements a small CSS cascade covering type, class, id, descendant and child selectors, inline styles and the old presentational attributes. It does not do JavaScript, custom properties beyond simple substitution, flexbox, grid, or any layout. The browser extension has a real engine and uses getComputedStyle, so on the same document the two can disagree slightly and the extension is the more accurate of the two.
  • It cannot tell you whether the writing is any good. Contrast, spacing and order are measurable. Whether a benefit notice makes sense to the person who received it is not, and nothing here should be read as saying it does.
  • The plain language summary is machine written and can be wrong. It is off by default, it runs against a local model and never a hosted API, it is placed beside the original text, and it carries a visible note saying so.

Running it

legible audit corpus/benefit-notice.html
legible fix   corpus/benefit-notice.html --out readable.html --face atkinson
legible fix   corpus/public-notice.pdf   --out readable.html --summary
legible pdf-text corpus/public-notice.pdf

The browser extension is unpacked: load extension/ in Chrome from Manage extensions, Load unpacked. It asks for activeTab and scripting, and nothing else. It makes no network request of any kind, which is asserted in the test suite rather than promised here, because a benefit notice is not something anybody should be uploading to a server to have it made readable.
